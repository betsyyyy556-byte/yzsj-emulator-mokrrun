# 03 · 随心跑（MokrRun）适配运动世界：补丁清单与构建流程

> 原版 MokrRun 1.0.115 的目标应用是 `com.bxkj.student`（体适能）。
> 本文件记录把它改到 **运动世界校园** `com.zjwh.android_wh_physicalfitness` 上跑通定位/轨迹/打卡的全部改动。

## 1. 需要改的四处

### ① 包名（4 个文件）

`smali/com/mokrun/app/` 下把 `com.bxkj.student` 全量替换为 `com.zjwh.android_wh_physicalfitness`：

```
arrays.xml            （作用域候选列表）
ModuleEntry.smali     （hook 安装判定）
DeveloperActivity.smali
FloatService.smali
```

### ② 目标启动 Activity（关键）

原版写死：

```
com.zjwh.android_wh_physicalfitness.splash.SplashActivity      ← 不存在
```

真实类名是 **`.mvi.splash.SplashActivity`**。不改的话，悬浮窗「开始」拉起目标应用会抛
`ActivityNotFoundException`，**运行状态带不进目标进程**，表现为「点开始但位置不动」。

### ③ 默认起点

`MotionEngine.smali` 里两个 double 常量 + HTML 里的 `setView`：

```
原：39.908700, 116.397500   （天安门）
改：22.906047, 113.870808   （东莞理工学院 松山湖校区 假草运动场/田径场）
```

对应 smali 常量：`0x4036e7f2b239a390L` / `0x405c77bb517a4617L`

### ④ 伪造计步传感器 + 加速度计波形（本项目的实验性补丁）

见 `patches/smali/`：

| 文件 | 作用 |
|---|---|
| `FakeStepSensor.smali` | 伪造 `getDefaultSensor` / `getSensorList` 返回 STEP_COUNTER |
| `FakeStepSensor$Hook.smali` / `$ListHook.smali` | 上述两个 hook 的实现 |
| `FakeStepAccel.smali` / `$Hook.smali` | 改写 `dispatchSensorEvent` 里的加速度计数值为走路波形（3.125 Hz 正弦） |

## 2. 构建流程

```powershell
$JAVA = 'D:\pao\tools\jdk17\jdk-17.0.13+11\bin\java.exe'
$src  = 'D:\pao\out\patch2\src'      # apktool 解码目录

# 1) 解码
& $JAVA -jar apktool.jar d MokrRun-1.0.115.apk -o $src -f

# 2) 改 smali / xml（见上）

# 3) 回编译（务必加 -f，见坑①）
& $JAVA -jar apktool.jar b $src -o out.apk -f

# 4) 签名
& $JAVA -jar uber-apk-signer.jar -a out.apk --allowResign -overwrite

# 5) 安装并修 Vector 登记 + 重启实例
& $ADB install -r out.apk
```

## 3. 踩过的坑（全部真实发生）

### 坑① apktool 缓存导致改动不生效

回编译时输出：

```
I: smali has not changed.
```

→ 用的是缓存里的旧 dex。**必须 `-f` 强制重建**，或先删除 `src\build`。
本项目前 5 个补丁版本全部因为这个"假生效"而白测。

### 坑② 中文写文件带 BOM → smali 编译失败

```
FakeStepSensor$Hook.smali[1,0] required (...)+ loop did not match anything at input '?'
```

用 PowerShell `Set-Content -Encoding UTF8` 会写 BOM。改为：

```powershell
[IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding($false)))
```

### 坑③ Vector 的 XposedBridge 只有单参数 log

```java
XposedBridge.log(String, String)   // 不存在！
java.lang.NoSuchMethodError: No static method log(Ljava/lang/String;Ljava/lang/String;)V
```

只能用 `XposedBridge.log(String tag)` 单参数版本。

### 坑④ smali 里的布尔判断写反（第一次调用直接 return）

```smali
sget-boolean v0, sInstalled:Z
if-eqz v0, :go        # 正确：未安装则继续
return-void           # 已安装则返回
:go
```

写成 `if-nez` 就变成"第一次调用直接返回"，钩子永远装不上，且**没有任何日志**——极难排查。

### 坑⑤ 类加载器

`XposedHelpers.findClass("android.hardware.SystemSensorManager", null)` 在 Vector 下取不到；
用 `Class.forName("android.hardware.SystemSensorManager")` 才行（boot class）。

## 4. 参数与实测

| 参数 | 值 | 说明 |
|---|---|---|
| speed | 2.8–4.8 m/s | 模块配置值；实测推进约为配置的 0.9–1.0 倍 |
| cadence | 2.8–4.0 步/秒 | 换算 168–240 步/分 |
| stride | 自动 | speed = cadence × stride |
| 起点 | 22.906047, 113.870808 | 假草运动场 |
| 路线 | 67 点 / 2.24 km | 沿田径场一圈 |

实测（补丁版 + 引擎运行中）：

```
0.03 km → 0.20 km → 0.41 km → 1.73 km（约 11 分钟）
配速 6′16″ / GPS 三格 / 打卡 5/5 全通过
步频 0（这是本方案无法解决的缺口）
```

## 5. 数据持久化的坑

MokrRun 的真正配置不在 `/data/data/com.mokrun.app/shared_prefs/`，而在**加密存储**：

```
/data/misc/<uuid>/prefs/com.mokrun.app/mokr.xml
```

只改 `/data/data/...` 那份，界面依旧显示默认值（天安门）。两份都要覆盖并修属主/上下文。

## 6. 状态位

引擎是否推进由 `Settings.Global.mokr_run` 驱动：

```powershell
& $ADB shell "settings put global mokr_run 1"   # 运行
& $ADB shell "settings put global mokr_run 2"   # 暂停
```

这条在调试时非常有用：**可以绕过悬浮窗直接让引擎跑起来**（悬浮窗按钮 adb 点不动）。
