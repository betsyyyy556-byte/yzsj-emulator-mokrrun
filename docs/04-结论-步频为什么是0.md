# 04 · 结论：为什么模拟器上步频永远是 0

## 1. 成绩页给出的判定（真实截图）

```
成绩未达标
检测到跑步数据异常，本次成绩无效

未达标原因
✔ 按顺序通过所有点位
✔ 最少要跑 1.00 公里
！步频控制在 60 步/分钟 - 300 步/分钟之间
✔ 配速控制在 2′00″ - 10′00″
！分段不达标
```

除步频（及其连带的"分段"）之外，**其它项全部通过**。

## 2. 证据链

### ① 系统层面没有计步传感器

```bash
$ adb shell dumpsys sensorservice | grep -i -E 'step|accelerometer'
0000000000) 3-axis Accelerometer | STMicro | type: android.sensor.accelerometer(1)
```

只有加速度计，`STEP_COUNTER(19)` / `STEP_DETECTOR(18)` 不存在。

### ② 传感器 HAL 本身缺配置

```
SensorsMultiHal: Failed to load subHal config file: /odm/etc/sensors/hals.conf
```

### ③ 模块的注入方式依赖传感器

MokrRun 源码 `SensorHook.java`（可对照 `patches/smali/SensorHook.smali`）：

```java
// RegHook：只记录 STEP_COUNTER / STEP_DETECTOR 类型的监听器
// pushStep()：只往这些监听器推步数
```

也就是说：**应用必须先注册到 step 类型传感器，模块才有"接收方"**。
模拟器没有这个传感器 → 应用注册不上 → 没有接收方 → 步频恒 0。

### ④ 应用侧确实在取传感器

```
dumpsys sensorservice 连接记录：
pid=9228 uid=10056 samplingPeriod=66667us ... (3-axis Accelerometer)
```

uid 10056 就是运动世界，它注册了加速度计，但拿不到步数。

### ⑤ 尝试伪造传感器（失败）

在模块里新增 `FakeStepSensor`，hook `SystemSensorManager.getDefaultSensor(int)` /
`getSensorList(int)`，当类型为 18/19 时返回一个自造的 `Sensor` 对象（mName/mType/mMaxRange/…全部补齐）。

结果：hook 安装成功（`MokrRun accel waveform hook installed`），但运动世界**从未调用**
`getDefaultSensor(19)` / `getSensorList(19)` —— 日志里一条命中记录都没有。

### ⑥ 改为注入加速度计波形（也失败）

hook `SystemSensorManager$SensorEventQueue.dispatchSensorEvent`，
把 `values[]` 改写成 3.125 Hz 的正弦（模拟步态）：

```smali
values[0] = 0.15 * sin(2π * (now % 320) / 320)
values[1] = 0
values[2] = 9.8 + 2.5 * sin(...)
```

结果：hook 生效（日志确认，参数长度 4，`args[3]` 为 `SensorEvent`），
但运动世界的 `步频` 依旧 0 → **说明它并不依赖加速度计推算步频，只认 STEP_COUNTER 的数值**。

### ⑦ 应用内部的降级开关也验证过

运动世界 dex 里存在这些 prefs 键：

```
step_calc_method   step_calc_snapshot   step_counter_available
step_counter_baseline_reset   step_delta   step_detector_available
step_final_capped  step_final_raw   step_freq_json  step_listen_start
```

说明它确实有"没有传感器时的降级算法"，但该算法在我们伪造的数据源上同样产不出有效步数。

## 3. 结论

| 层 | 结论 |
|---|---|
| 硬件/镜像 | 无 STEP_COUNTER / STEP_DETECTOR，HAL 配置缺失 |
| 模块 | 步数注入依赖上述传感器，无法自行造数 |
| 应用 | 步频只认 STEP_COUNTER，加速度计波形无效 |
| 结果 | **模拟器路线无法产出合规步频，成绩必然无效** |

## 4. 在真机上这条路线是通的

真机自带计步传感器，MokrRun 的 `pushStep` 天然有接收方，步频会显示 160–180。
也就是说：**这套方案本身没错，错在"跑在没有计步硬件的模拟器上"**。

## 5. 顺带确认：视频里的方案不是随心跑

该视频（BV1rrWg6tE13）界面特征为：

- 设置页有 `伪造 Wi-Fi 数据 / 模拟基站数据 / 模拟蓝牙数据 / 真实道路匹配 / 到达终点后停下 / 开启轻微抖动`
- 结尾是「定点模拟」+ 手动输入经纬度

这些是 **LocationSpoofer** 的功能，随心跑只有 `目标速度 / 步频上限 / 步长 / 检测绕过` 四项。
LocationSpoofer 的步数由 App 自己生成（不依赖系统传感器），所以它在模拟器上能出步频。
