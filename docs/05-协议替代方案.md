# 05 · 协议替代方案：绕开模拟器与传感器

> 本文件只记录**方法可行性**与**结果字段**，不包含任何账号、密码、token、学校信息等敏感数据。

## 1. 思路

模拟器方案的死结是"必须由设备提供传感器数据"。
换一个思路：不跑 App，直接按 App 的协议向服务端**提交一次完整跑步记录**。

参考开源实现（纯 Python，分析 App 网络协议后重构）：

- `Inverx/com.zjwh.android_wh_physicalfitness` —— 运动世界校园协议分析

关键点在于它还原了：

```
NetSecKit 4.2.4 加密（AES-128-CBC + Feistel KDF + RSA PKCS#1 v1.5）
headerSign / tokenSign 请求头签名
极验 v4 滑块（GeeTest v4）自动识别
华为云 OBS 轨迹直传（Gzip + Base64）
31 字段运动学参数的 MD5 签名（含加盐）
```

## 2. 环境

```
Python 3.10+          （核心逻辑只用标准库）
Node 18+ + Playwright （仅在需要过极验滑块时使用）
Playwright Chromium   （约 130 MB）
```

## 3. 执行链路（实测跑通）

```bash
python cli.py --sync-time                      # 1. 服务端时间对齐
python cli.py -u <手机号> -p <密码>             # 2. 登录（含滑块自动识别）
python cli.py -t <Token> --uid <UID> --profile --rules   # 3. 档案与规则
python cli.py -t <Token> --uid <UID> --checkpoints       # 4. 官方打卡点
python cli.py -t <Token> --uid <UID> --run --mode 1 --distance 1900 --time-sec 700
python cli.py -t <Token> --uid <UID> --history           # 5. 回查
```

## 5. 与模拟器方案对比

| | 模拟器 + MokrRun | 协议直连 |
|---|---|---|
| 需要 Root / LSPosed | 是 | 否 |
| 需要模拟器 | 是 | 否 |
| 依赖计步传感器 | **是（因此失败）** | 否 |
| 步频 | 0 | 230（按规则生成） |
| 判定结果 | 未达标 | 四项全绿 |
| 主要风险 | 模块与 App 版本绑定，一次更新全废 | 协议与 App 版本绑定（7.3.92 / 7.3.40） |

## 6. 已知限制

1. **协议与 App 版本强绑定**：仓库按 `7.3.92` / `7.3.40` 维护，App 大版本变化需要重新做协议 diff。
2. **会把 App 挤下线**：协议登录被视为"另一台设备"，App 端会提示
   「此账号已在其他设备登录…请过一小时后登录」。仓库内没有 logout 接口（试了 5 个路径均 404）。
3. **单日上限**：本次学校规则是单次≥1000 m、单日≤2000 m，所以一次提交按 1900 m 比较稳妥。
4. 服务端有风控（例如境外 IP 直连会被网关返回 `HTTP 567`，需使用本地网络出口）。
