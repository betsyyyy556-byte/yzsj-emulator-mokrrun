# 06 · 登录会话冲突与设备指纹

> 本文记录协议直连方案的一个副作用：**协议登录会把手机端顶下线**，以及为什么
> "App 里退出登录"、"改密码"都解不开，和工程上怎么避免复发。

---

## 1. 现象

在电脑上用协议登录过一次之后，手机 App 再登录会提示：

```
登录失败，此账号已在其他设备登录，因账号保护机制，原状态未退出；
请过一小时后登录或原设备退出后再登录
```

同一时间，电脑端的协议 token **仍然有效**（能正常查档案、规则、历史）。

---

## 2. 为什么"退出登录"和"改密码"都没用

### ① App 的「退出登录」只清本地

对 App 的 dex 做字符串扫描，`logout` 相关的 22 处全部是 UI 文案和华为账号 SDK：

```
ic_setting_logout / tv_logout / msg_logout / txt_logouting      ← 界面文字
hwid.logout / hwid.signout                                       ← 华为账号 SDK
```

没有任何一条是 App 自己的 HTTP 退出接口。也就是说：**App 点退出 = 本地清 token，服务端不知道**。

而服务端那条"在线"记录属于**协议客户端那台"虚拟设备"**，与手机是两条独立会话，
所以在手机上退出，退不掉协议这条。

### ② 改密码不会作废已签发的 token

实测：手机端完成密码重置后，协议端的旧 token **依然能查到个人档案**。
说明该服务端的 token 不是"密码哈希派生 + 即时失效"的模型，改密码不会吊销会话。

### ③ 没有可用的 logout 接口

对 91 个候选路径做过探测（`/api/{v1,v3,v65,v76,v70000,v70100,v70260,v70270,v70300,v70320,v70390,v76200,v76300}/`
× `{logout, loginOut, user/logout, account/logout, user/loginOut, login/logout, account/loginOut}`），
**全部返回 404**。

结论：只能等会话自然过期（服务端策略约 1 小时无活动），或由客服后台强制下线。

---

## 3. 关键：协议请求会"续命"

排查过程中发现一个坑：**每一次协议请求都会刷新该会话的活跃时间**。

时间线（实测）：

```
11:59  协议登录成功            → 锁开始计时
12:32  用协议查档案 + 规则      → 活跃时间刷新，锁顺延
13:06  手机尝试登录 → 仍被拦
13:22  再用协议查一次 token     → 又顺延
```

所以正确做法是：**决定让手机登录后，就完全停止一切协议请求**，等窗口自然过期。

---

## 4. 设备指纹：为什么会越登越多

旧版协议实现（`--depth 1` 拉到的历史版本）在每次运行时**随机生成设备配置**
（型号、系统版本、屏幕、DeviceId、androidId），于是：

- 每登录一次，服务端就认为"又来了一台新设备"
- 设备槽位越占越多，越容易撞上"其他设备登录"
- 重启程序设备又变，无法复现

上游的一个 PR（`Zephyr-Lyu:codex/protocol-audit-fixes`，对应 issue #14 的修复）解决了这个问题：

> 新增按手机号持久化设备配置：首次选择型号及匹配的系统/屏幕字段，
> 生成独立 DeviceId、androidId 和安装时间；以后自动读取。
> 登录成功后关联 UID，后续 `-t --uid`、独立查询客户端以及后设置凭据均复用同一配置。

实现要点：

```
core/devices.py          DeviceStore：按 account/uid 绑定设备，原子写入 + 文件锁
.device_profiles/devices.json   默认存储位置（可用 --device-dir 或 SPORT_DEVICE_DIR 覆盖）
只存设备字段与账号哈希，不存密码 / Token / 原始手机号
```

**工程建议**：把 `device_dir` 指向固定目录（本项目用 `D:\YZSJ\.device_profiles`），
这样即使升级/替换程序目录，设备指纹也不会丢。

---

## 5. 实操建议

| 场景 | 做法 |
|---|---|
| 需要手机 App 保持在线 | 不要用协议登录；或登录后立刻停用，等窗口过期再上手机 |
| 只在电脑跑成绩 | 一次性登录拿到 token 后长期复用，不再重复登录 |
| token 过期要重登 | 先确认手机端是否在用；必要时先让手机退出并等待窗口 |
| 已经撞上"其他设备登录" | 停止一切协议请求，等约 1 小时后手机重登；不行就找客服强制下线 |
| 想减少冲突 | 使用带设备持久化的版本，固定一台"虚拟设备" |

---

## 6. 一句话总结

> 这个服务端把"协议客户端"当成一台真实设备来做设备互踢，
> 而 App 的退出登录并不通知服务端，改密码也不吊销 token，
> 所以冲突只能靠**停用协议 + 等窗口过期**，或**客服强制下线**来解。
> 长期方案是固定设备指纹，减少"新设备"的诞生。
