# 运动世界校园 · 模拟器方案实验记录（无步频版）

> 目标应用：**运动世界校园** `com.zjwh.android_wh_physicalfitness`
> 实验环境：MuMu 模拟器 6.0 / Android 15 (SDK 35) / x86_64 / KernelSU Root + LSPosed(Vector)
> 状态：**模拟器路线定位/轨迹/打卡点/里程/配速全部跑通，但步频恒为 0 → 成绩判定无效**
> 结论：模拟器没有计步传感器，这条路走不通；同一天改用协议直连服务端跑通，四项判定全绿。

---

## 一、结论先看这里

| 判定项 | 模拟器 + 随心跑 | 协议直连 |
|---|---|---|
| 按顺序通过所有点位 | ✅ | ✅ |
| 最少跑 1.00 公里 | ✅（1.73 km / 1900 m） | ✅ |
| 配速 2′00″–10′00″ | ✅（6′16″） | ✅（6′08″） |
| **步频 60–300 步/分** | ❌ **恒为 0** | ✅（230 步/分） |
| 最终判定 | 数据异常 / 无效 | 有效（status=0） |

**根因一句话**：MuMu 的 Android 15 镜像里**只有 3 轴加速度计，没有 `TYPE_STEP_COUNTER` / `TYPE_STEP_DETECTOR`**。
「随心跑 MokrRun」的步数注入是**借用系统传感器**的实现——它 hook `registerListener`，只对注册了 step 类型传感器的监听器推送步数。
没有传感器 → 应用注册不上 → 没有接收方 → 步频恒 0。

详见 [`docs/04-结论-步频为什么是0.md`](docs/04-结论-步频为什么是0.md)。

## 三、模拟器方案能做什么 / 不能做什么

**能**
- 在 MuMu 里把运动世界启动到「跑步中」界面
- 位置沿自定义路线推进（实测约 2–2.8 m/s），地图生成真实轨迹
- 5 个官方打卡点按顺序全部命中
- 里程、配速、GPS 质量、电子围栏全部表现正常（服务端判定这些项都通过）

**不能**
- 产生步频/步数（`avgStepFreq` 恒为 0），成绩最终被判「数据异常」

## 四、快速开始（复现模拟器方案）

前置：MuMu 模拟器 6.0 已安装、实例为 Android 15、开启 KernelSU 与 ADB。

```powershell
cd scripts
.\00_download.ps1        # 下载 ZygiskNext / Vector / Shamiko / HMA / MokrRun
.\01_connect.ps1         # adb 连接 + root
.\02_modules.ps1         # 安装内核模块并登记到 Vector
.\03_apps.ps1            # 安装目标应用与模块
.\04_hide.ps1            # 环境隐藏
.\05_verify.ps1          # 校验
```

细节与排错见 `docs/01`～`docs/03`。

## 五、协议路线（实际出成绩的那条）

不跑 App，直接按 App 协议向服务端提交跑步记录。参考开源实现：
[`Inverx/com.zjwh.android_wh_physicalfitness`](https://github.com/Inverx/com.zjwh.android_wh_physicalfitness)

它还原了 NetSecKit 4.2.4 加密、`headerSign`/`tokenSign` 签名、极验 v4 滑块、华为云 OBS 轨迹直传、31 字段 MD5 签名结算。

实测提交参数与结果：

```
距离 1900 m / 耗时 700 s / 配速 6'08" / 步频 230 步/分
点位 5/5 全通过 · 四项判定全绿 · status=0（有效）
```

**注意**：协议与 App 版本强绑定（仓库按 7.3.92 / 7.3.40 维护），大版本更新需要重做协议 diff。
且协议登录会被服务端视为「另一台设备」，App 端会提示「已在其他设备登录」——
机制说明见 [`docs/06-登录会话冲突与设备指纹.md`](docs/06-登录会话冲突与设备指纹.md)。

## 六、两个方案的对比

| | 模拟器 + 模块 | 协议直连 |
|---|---|---|
| 依赖设备传感器 | 是（所以失败） | 否 |
| 需要 Root/LSPosed | 是 | 否 |
| 步频 | 0 | 正常（按规则生成） |
| 判定结果 | 未达标 | 四项全绿 |
| 维护成本 | 高（App 一更新 hook 全废） | 中（协议版本绑定） |
| 副作用 | 无 | 会顶掉手机端登录 |
